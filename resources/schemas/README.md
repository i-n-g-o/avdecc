# Different JSON schemas

This directory contains the JSON schemas used to validate the JSON dump files generated by the library.
- The `common` directory contains common schema definitions used by the other schemas.
- The `AEM` directory contains the schemas used to validate the JSON dump files generated by the library for the AEM entity model tree (.AEMT files). The entity model is the static model only (what is defined by the firmware of an entity), it never describes the dynamic model.
- the `AVE` directory contains the schemas used to validate the JSON dump files generated by the library for a Virtual Entity or Entity Model (.AVE and .AEM files). The static part of the entity model is validated using the AEM schema, its dynamic part (when present) is described by the AVE schema itself.
- the `ANS` directory contains the schemas used to validate the JSON dump files generated by the library for a Network State (.ANS files), which contain all the entities known by a controller.

A value not defined by the library (out of specification, or from a more recent specification) is never lost: it is serialized as the hexadecimal representation of its underlying value (eg. `"0x0020"` for an unknown MEMORY_OBJECT type), and a string that is not a valid UTF-8 string (cannot be represented as a JSON string) is serialized as an array of its bytes. The schemas must accept these representations.

# How to update the JSON schemas

The algorithm used by the library to generate dump files that comply with the schemas can be found in the following source files:
- For the entity model tree, see the `src/entity/entityModelJsonSerializer.cpp` file.
- For the static (AEM schema) and dynamic (AVE schema) descriptors properties, see the `include/la/avdecc/internals/jsonTypes.hpp` file.
- For more details about the descriptors themselves, see the `include/la/avdecc/internals/entityModelTreeStatic.hpp` and `include/la/avdecc/internals/entityModelTreeDynamic.hpp` files.
- For the other information of a virtual entity (ADP, compatibility, state, statistics, diagnostics), see the `src/controller/avdeccControlledEntityJsonSerializer.cpp` and `src/controller/avdeccControllerJsonTypes.hpp` files.
- For the network state, see the `ControllerImpl::serializeAllControlledEntitiesAsJson` method in the `src/controller/avdeccControllerImplOverrides.cpp` file.

## Common schema
The common definitions are stored in a subfolder of the `common` directory which is named after their `schema_version`. When a change is required, a new subfolder should be created (so the schemas referencing a previous version are not altered), and the schemas using the new definitions should be updated to reference it.

## AEM schema (AEMT files)
When a new `aem format version` is released, a new AEM schema named `schema.json` should be created and stored in a subfolder of the `AEM` directory which is named after the `aem format version`. The `aem_format_version` field should strictly check for the exact version of the AEM file. The `aem_format_version` is controlled by the `Node_FormatVersion` variable from `include/la/avdecc/internals/jsonTypes.hpp`.

When a minor revision of a schema needs to be made, simply update the `schema_version` field in the affected `schema.json` file.

## AVE schema (AVE and AEM files)
When a new `dump version` is released, a new AVE schema named `schema.json` should be created and stored in a subfolder of this directory which is named after the `dump version`. The `dump_version` field should strictly check for the exact version of the dump file. The `dump_version` is controlled by the `ControlledEntity_DumpVersion` variable from `src/controller/avdeccControllerJsonTypes.hpp`.

When a minor revision of a schema needs to be made, simply update the `schema_version` field in the affected `schema.json` file.

## ANS schema (ANS files)
When a new network state `dump version` is released, a new ANS schema named `schema.json` should be created and stored in a subfolder of the `ANS` directory which is named after the `dump version`. The `dump_version` field should strictly check for the exact version of the dump file. The `dump_version` is controlled by the `Controller_DumpVersion` variable from `src/controller/avdeccControllerJsonTypes.hpp`.

A network state file contains entities dumped using the `ControlledEntity_DumpVersion` of the library that generated it, so the ANS schema must accept all the AVE schemas versions.

When a minor revision of a schema needs to be made, simply update the `schema_version` field in the affected `schema.json` file.
